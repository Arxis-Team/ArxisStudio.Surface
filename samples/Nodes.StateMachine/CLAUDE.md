# CLAUDE.md

Пример `Nodes.StateMachine` — машина состояний на редакторе узлов, которая ведёт живой интерфейс
Avalonia. Файл грузится, когда работают под этим каталогом; про саму библиотеку сказано в `CLAUDE.md` в
корне репозитория, про демо узлов — в `samples/Nodes.Demo/CLAUDE.md`.

Как и демо узлов, пример — проверка библиотеки на потребителе: написан только на публичном API
`ArxisStudio.Surface.Nodes`, и библиотеку ради него не меняли.

## Что на экране

Слева — холст с машиной, справа — «Приложение»: экран активного состояния и журнал переходов. Сверху —
«▶ Запустить» / «■ Остановить», переключатель «Сеть», «Пример» (вернуть исходную машину), «Показать всё»,
отмена и повтор.

## Модель (`Machine/`)

- **Состояние** — `StateNode`: показывает один экран приложения (`AppScreen`: вход, проверка, ошибка
  входа, главная, карточка, настройки, нет сети); название — название экрана.
- **Переход** — тоже узел, `TransitionNode`: его название — условие (`Trigger`). Условие видно на холсте
  так же, как название состояния: подписей на проводе у библиотеки нет, а узел-переход обходится без
  неё, как Transition Rule в Blueprint.
- **Вход** — `EntryNode`, одна связь в начальное состояние; **любое состояние** — `AnyStateNode`: его
  переходы проверяются, где бы машина ни стояла; **узел перенаправления** — `RerouteNode`, излом провода.
- **Связь** — `FlowLink`, поток управления: светлый провод, как провода исполнения в Blueprint. Цвет —
  модели (`LinkStrokeBinding="{Binding Color}"`); вспышку сработавшего провода рисует редактор
  импульсом (ADR 0014 библиотеки), модель о ней не знает.

Правила связи — `MachineDocument.CanConnect`, а окно отдаёт их редактору через `ConnectValidating`:
состояние принимает сколько угодно переходов; у перехода и узла перенаправления один вход и один выход; у входа —
одно начальное состояние; из состояния в состояние напрямую ведёт только вход; из перехода в переход и
одинаковую связь дважды — нельзя. Путь из состояния читается через узлы перенаправления (`Follow`).
Провод через узлы перенаправления — один провод: удалённый кусок, разрез или удалённый узел уносят и
узлы перенаправления, оставшиеся без входа или без выхода, вместе с их прочими связями
(`MachineDocument.Stranded`), одной записью истории. Касательные узла перенаправления разворачивает по
проводу редактор, как в Blueprint (ADR 0013 библиотеки): обратный переход, сломанный двойным щелчком,
не закручивается.

**Условие** (`Trigger`) — событие интерфейса, наименьшее время в состоянии и проверка приложения
(`MachineContext`: логин, пароль, есть ли сеть, открытая строка). Набор — `Triggers.All`: нажатия
«Войти», «Повторить», «Открыть», «Назад», «Настройки», «Выйти»; «1,5 с · пароль верный» и «… неверный»;
«нет сети» и «сеть вернулась»; «через 3 с».

## Запуск (`MachineRunner`)

Такт — 50 мс, как кадр для правил переходов Unreal: проверяются переходы активного состояния, потом
«любого», по порядку коллекции связей, и срабатывает первый, чьё условие выполнено. Событие интерфейса
живёт один такт: не нужное ни одному переходу, оно пропадает. Из «любого состояния» в то, где машина
уже стоит, не переходят: условие «нет сети» держится, и машина входила бы в «Нет сети» на каждом такте.

Граф машина читает живым: правка на холсте во время работы действует со следующего такта — смена
условия перехода контекстным меню сразу меняет, куда пойдёт машина, — а удалённое активное состояние
останавливает её.

**Показ — как отладка State Machine в Unreal:** активное состояние — в янтарной рамке и считает время
(«▶ 2,4 с»), сработавший переход пишет «сработал», покинутое состояние гаснет за секунду. Провода
пути перехода зажигает редактор: машина поднимает `Fired` с проводами пути, окно зовёт
`Editor.PulseLink` по каждому, и по проводу бегут пузыри со свечением, как по проводам исполнения
Blueprint (ADR 0014 библиотеки); остановка машины гасит всё `ClearLinkPulses`. Панель: «Импульсы» и
«Маркеры» — выключатели редактора (`IsLinkPulseEnabled`, `AreLinkMarkersVisible`) привязкой, списки —
фигура импульса (`LinkPulse`) и маркера посередине провода (`LinkMarker`). Выключенные, они не
отвлекают, пока проверяют само приложение; включённые снова, возвращаются теми же. Модель ставит узлу `Look` (`Active`, `Trace`), а окно — класс
`active` или `trace` его контейнеру, и стили окна красят карточку узла
(`surface|Node.active /template/ Border#PART_Card`). Класс ставится и развёрнутому заново контейнеру
(`ContainerPrepared`) и снимается с отданного в пул (`ContainerClearing`). Селектор с классом — триггер
стиля, и он сильнее значения, которое ставит шаблон карточки.

## Приложение (`Preview/AppPreview.cs`)

Экраны — обычные контролы Avalonia (Fluent). Их кнопки не меняют экран сами, а поднимают событие
машины (`MachineRunner.Fire`): куда перейти, решает граф на холсте. Введённое — логин, пароль, выбранная
строка — пишется в `MachineContext`. Настройки правда переключают тему окна. Верный пароль —
`avalonia`, подсказка стоит на экране входа.

## Контекстное меню (`MachineContextMenu.cs`)

Поставщик действий библиотеки (`ISurfaceContextActionProvider`) в `Editor.ContextActionProviders`.
По пустому холсту: «Состояние ▸ экран», «Переход ▸ условие», «Любое состояние», «Вход» (если его нет),
«Узел перенаправления», «Показать всё» — узел встаёт в точку щелчка (`request.WorldPoint`). По узлу: у состояния
«Экран ▸», «Сделать начальным», «Удалить»; у перехода «Условие ▸», «Удалить». Узел под курсором —
`editor.ItemFromContainer(request.Target.Container)`. Каждая правка — запись `SurfaceHistory` окна
(`ListEdit`, `CompositeChange`, `PropertyChange`), и Ctrl + Z её отменяет.

## Раскладка примера

Провод выходит вправо и входит слева, поэтому машина читается слева направо по главному ряду.
Обратный переход стоит слева от состояния, в которое возвращает, на своей полосе выше или ниже главного
ряда: длинный провод идёт по полосе, а в состояние входит короткий. Выход с главной возвращается ко входу
узлами перенаправления по нижнему краю. При открытии окно вписывает машину (около 56 %); упрощённый вид у редактора узлов
начинается ниже 30 % (ADR 0013 библиотеки), и названия видны при любом разумном отдалении.

## Проверка вживую

Запускать собранный exe, а не `dotnet run`. MCP DevTools — с `AVA_DEVTOOLS_MCP=1`,
`AVA_DEVTOOLS_MCP_PORT=5177` (5171–5176 заняты студией, витринами и демо), `AVA_DEVTOOLS_MCP_INPUT=1`.
Снимок окна — `PrintWindow`: `screenshot` DevTools рисует дерево заново, мимо композитора. Закрывать —
по номеру процесса.

Что проверено так: запуск; неверный пароль → «Ошибка входа», «Повторить» → вход; верный → через 1,5 с
«Главная»; «Открыть» → «Карточка», «Назад» → «Главная»; «Сеть» выкл. → «Нет сети» из любого состояния,
вкл. → вход. Контекстное меню: «Состояние ▸ Настройки» добавляет узел, «Условие ▸ через 3 с» меняет
переход, и запущенная машина сразу идёт по новому условию; две отмены возвращают всё. Импульс: щелчок
«Войти» светит янтарём оба провода перехода, пузырь между двумя снимками через 300 мс сдвигается ко
входу; стрелки стоят посередине каждого провода. Импульс живёт 1,4 с, а снимок `PrintWindow` через
PowerShell запаздывает на секунду-две — ловить его надо `screenshot` DevTools сразу после щелчка.

Две ловушки MCP: `find_elements` в попапы не заглядывает — пункты контекстного меню находят деревом
попапа (`list_popups`, `get_tree`, заголовок — `get_element`); `press_key` берёт `keys`, а не `key`, и
неизвестный параметр не отвергается.
